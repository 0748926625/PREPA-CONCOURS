# CRÉATION D’UNE PWA DE RÉVISION INTELLIGENTE PAR QCM

## 1. OBJECTIF DU PROJET

Je veux créer une Progressive Web App (PWA) permettant aux utilisateurs de réviser efficacement à partir de ressources pédagogiques ou professionnelles qu’ils fournissent.

Les ressources peuvent être par exemple :

* Cours PDF
* Documents Word
* Textes
* Supports de formation
* Statut général de la Fonction publique
* Lois et règlements
* Guides professionnels
* Manuels
* Notes de cours
* Documents administratifs
* Tout autre document contenant des informations exploitables pour créer des questions

L’application utilise l’intelligence artificielle pour analyser les ressources et générer automatiquement des QCM interactifs.

L’objectif principal est de créer une boucle :

**RESSOURCE → QCM → ÉVALUATION → DÉTECTION DES LACUNES → REMÉDIATION → NOUVELLE ÉVALUATION**

L'application doit être extrêmement simple à utiliser, rapide et adaptée aux smartphones.

---

# 2. STACK TECHNIQUE

Construire une PWA moderne avec :

* React
* TypeScript
* Vite
* Tailwind CSS
* React Router
* Supabase pour la base de données et l’authentification
* API IA facilement interchangeable
* PWA installable sur Android, iPhone et ordinateur
* Design responsive mobile-first

Utiliser une architecture simple et propre.

Ne pas ajouter de technologies inutiles au MVP.

---

# 3. PRINCIPE DE FONCTIONNEMENT

L'utilisateur doit pouvoir :

1. Créer un compte ou utiliser l'application selon le mode prévu.
2. Ajouter une ressource.
3. Donner un titre à la ressource.
4. Importer un PDF ou saisir/copier du texte.
5. L'application analyse le contenu.
6. L'IA identifie les notions importantes.
7. L'IA génère des QCM.
8. L'utilisateur répond aux questions.
9. L'application corrige immédiatement ou à la fin du test.
10. L'application calcule les résultats.
11. Elle identifie précisément les notions mal maîtrisées.
12. Elle génère automatiquement une séance de remédiation.
13. L'utilisateur réalise les exercices ciblés.
14. Une nouvelle série de questions vérifie si la notion est désormais maîtrisée.

# 6. ANALYSE DES DOCUMENTS PAR L'IA

Lorsqu'une ressource est ajoutée, l'application doit extraire son contenu.

L'IA doit analyser le document afin d'identifier :

* Les notions importantes
* Les définitions
* Les règles
* Les dates
* Les chiffres
* Les conditions
* Les exceptions
* Les procédures
* Les concepts
* Les relations entre concepts

Créer ensuite une structure de connaissances exploitable.

IMPORTANT :

Les questions doivent être générées UNIQUEMENT à partir du contenu réellement présent dans la ressource.

Ne pas inventer d'informations.

Pour chaque question générée, conserver si possible :

* la ressource d'origine
* la notion concernée
* le passage ou la page d'origine
* l'explication de la réponse

Cela permettra d'expliquer à l'utilisateur pourquoi sa réponse est incorrecte.

---

# 7. GÉNÉRATION DES QCM

Créer automatiquement des questions à choix multiples.

Chaque question possède :

* Question
* 3 ou 4 propositions
* Une seule bonne réponse
* Explication de la bonne réponse
* Notion évaluée
* Difficulté
* Référence à la ressource
* Page ou section d'origine lorsque cette information est disponible

Exemple :

QUESTION :

"Selon le Statut général de la Fonction publique, ..."

A. ...
B. ...
C. ...
D. ...

Après réponse :

✓ Bonne réponse

ou

✗ Mauvaise réponse

Puis afficher :

"Bonne réponse : B"

"Explication : ..."

"Cette question évalue la notion : Les obligations du fonctionnaire."

---

# 8. MODES DE RÉVISION

Prévoir plusieurs modes simples.

## Mode 1 — Révision rapide

10 questions aléatoires.

## Mode 2 — Révision complète

Toutes les questions disponibles sur une ressource.

## Mode 3 — Mes lacunes

L'application sélectionne uniquement les notions sur lesquelles l'utilisateur a obtenu de mauvais résultats.

## Mode 4 — Remédiation

L'application génère une séance spécialement conçue pour corriger les erreurs de l'utilisateur.

---

# 9. SYSTÈME DE DÉTECTION DES LACUNES

C'est une fonctionnalité centrale de l'application.

Ne pas simplement calculer le score global.

L'application doit déterminer :

* Quelles notions sont maîtrisées
* Quelles notions sont moyennement maîtrisées
* Quelles notions sont mal maîtrisées
* Quelles notions n'ont jamais été évaluées

Exemple :

RESSOURCE : Statut général de la Fonction publique

Résultats :

* Droits et obligations : 90% — Maîtrisé
* Discipline : 75% — À renforcer
* Congés : 45% — Lacune
* Avancement : 35% — Lacune
* Rémunération : 82% — Maîtrisé

Afficher visuellement ces informations.

---

# 10. REMÉDIATION INTELLIGENTE

Lorsqu'une lacune est détectée, l'application doit proposer une remédiation.

Exemple :

"Lacune détectée : Les conditions d'avancement"

Afficher :

### 1. Rappel

Un résumé très simple de la notion.

### 2. Exemple

Un exemple permettant de comprendre la notion.

### 3. Exercices

Créer 3 à 5 questions ciblées.

### 4. Vérification

Créer ensuite de nouvelles questions différentes permettant de vérifier la compréhension.

IMPORTANT :

La remédiation doit être ciblée.

Si l'utilisateur échoue sur une notion précise, ne pas lui faire refaire tout le chapitre.

---

# 11. ALGORITHME SIMPLE DE MAÎTRISE

Pour chaque notion, conserver :

* nombre de questions
* nombre de bonnes réponses
* nombre de mauvaises réponses
* dernier score
* nombre d'échecs consécutifs
* niveau de maîtrise

Utiliser par exemple :

0–49 % → "À revoir"

50–69 % → "Fragile"

70–84 % → "En bonne voie"

85–100 % → "Maîtrisé"

Les seuils doivent être facilement modifiables dans le code.

Une notion considérée comme maîtrisée doit néanmoins pouvoir redevenir "À revoir" si l'utilisateur échoue plusieurs fois dessus.

# 17. IA

Créer une couche d'abstraction permettant de changer facilement de fournisseur d'IA.

Par exemple :

AI_PROVIDER = "gemini"

ou

AI_PROVIDER = "openai"

Ne jamais mettre les clés API directement dans le frontend.

Les appels IA doivent passer par une fonction serveur sécurisée.

Créer des fonctions distinctes :

* extractDocument()
* analyzeResource()
* generateQuestions()
* generateRemediation()
* analyzeWeaknesses()

Les prompts IA doivent être centralisés et facilement modifiables.

---

# 18. PROMPT DE GÉNÉRATION DES QUESTIONS

L'IA doit recevoir le contenu du document et produire des questions structurées.

Règles :

* Ne jamais inventer une information.
* Utiliser exclusivement le contenu fourni.
* Une seule réponse correcte.
* Les distracteurs doivent être plausibles.
* Éviter les questions ambiguës.
* Éviter les formulations permettant de deviner facilement la réponse.
* Varier la position de la bonne réponse.
* Mélanger les difficultés.
* Associer chaque question à une notion.
* Fournir une explication.
* Indiquer la source lorsque possible.

Retourner les données dans un format JSON strict.

---

# 19. PROMPT DE REMÉDIATION

Lorsqu'un utilisateur échoue plusieurs fois sur une notion :

L'IA reçoit :

* la notion
* le contenu source
* les questions échouées
* les réponses données
* les bonnes réponses
* les explications

Elle doit déterminer la cause probable de l'erreur et générer :

1. Un rappel très court.
2. Une explication pédagogique.
3. Un exemple.
4. 3 à 5 exercices ciblés.
5. Une nouvelle série de questions de vérification.

La remédiation doit éviter de simplement répéter les mêmes questions.

* professionnel
* épuré
* très lisible
* mobile-first
* adapté à la révision
* peu chargé

Utiliser des cartes, des indicateurs de progression et des couleurs sémantiques :

* rouge = lacune
* bleu = information

Ne pas surcharger l'écran.

# 22. MODE HORS CONNEXION

Prévoir l'architecture pour permettre à terme :

* consultation des ressources déjà téléchargées
* consultation des questions déjà générées
* réalisation de QCM hors connexion
* synchronisation des résultats lorsque la connexion revient

Pour le MVP, implémenter uniquement ce qui est nécessaire pour rendre les QCM déjà chargés utilisables hors connexion.

---

# 23. SÉCURITÉ

Respecter les bonnes pratiques :

* Les clés API ne doivent jamais être exposées au frontend.
* Utiliser les règles de sécurité Supabase.
* Chaque utilisateur ne doit accéder qu'à ses propres ressources et résultats.
* Valider les données provenant de l'IA.
* Ne jamais faire confiance directement aux réponses JSON de l'IA sans validation.

---

# 24. MVP — PRIORITÉ ABSOLUE

Ne cherche pas à construire immédiatement une plateforme complexe.

La première version doit uniquement permettre :

1. Ajouter/importer une ressource.
2. Extraire son contenu.
3. Générer automatiquement des QCM.
4. Répondre aux QCM.
5. Obtenir son score.
6. Identifier les notions mal maîtrisées.
7. Générer une remédiation.
8. Faire de nouveaux exercices ciblés.
9. Enregistrer la progression.

Tout ce qui n'est pas nécessaire à ces fonctionnalités doit être reporté.

1. Vérifie l'architecture existante.
2. Crée les fichiers nécessaires.
3. Implémente la fonctionnalité.
4. Vérifie les erreurs TypeScript.
5. Vérifie les erreurs de build.
6. Corrige les problèmes.
7. Ne casse pas les fonctionnalités existantes.

Ne génère pas une énorme quantité de code inutile.

Privilégie un code simple, maintenable et facilement modifiable.

# 28. OBJECTIF FINAL

L'application doit donner à l'utilisateur l'impression d'avoir un professeur particulier numérique.

Le système doit fonctionner ainsi :

"Je fournis mon cours."

↓

"L'application comprend mon cours."

↓

"Elle me pose des questions."

↓

"Elle voit ce que je maîtrise et ce que je ne maîtrise pas."

↓

"Elle m'explique mes erreurs."

↓

"Elle me donne des exercices adaptés à mes lacunes."

↓

"Elle vérifie que j'ai progressé."

↓

"Elle adapte les prochaines révisions à mon niveau."

Construis le MVP avec cette logique comme principe fondamental.
